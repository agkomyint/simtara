# SimTara v0.3.0: Save your work, run an experiment

**Status: built, waiting for a hands-on check and a release tag.** Differences from the plan: the experiment chart shows in a bottom panel; saved folders also hold `start.snap.json` per experiment.

Goal: a person can build a universe, **save it, close the app, reopen it**, then **run an experiment on it and see the result**. That is all.

Everything bigger (a template gallery, more kinds of universe, docking panels, sharing, hosted compute, accounts) is in [vision.md](vision.md) and is deliberately **not** in this release.

## Why only these two

Today you can launch a universe and watch it, but nothing you do is kept, and you can't test an idea and see whether it worked. These two features fix exactly that, and every later feature builds on them. Save/resume is the base for projects. Experiments are the base for results and hosted runs.

## Feature 1: Save and reopen a universe

What the user sees:
- In the Studio, a **Save** button (and autosave on exit).
- The launcher shows **My universes**: name, particle count, tick, last opened. Click one to continue where it stopped.

How it works:
- Each universe is a folder: `SimTara/universes/<name>/`
- Inside: `universe.json` (name, template, config, seed, created/updated) and `state.snap.json` (the saved world, which the engine already knows how to write).
- The files carry a `schema_version` number so old saves can still open after upgrades.

What already exists: snapshot save/load in the engine (`Simulation::save_to`, `read_snapshot`). What is new: the folder layout, `universe.json`, and the launcher list.

Done when: launch, change gravity, save, quit, reopen, and the same universe is on the same tick with the same settings.

## Feature 2: Run an experiment and see the result

What the user sees:
- A panel **Experiment**: choose one parameter (for example gravity), a second value to compare, a number of ticks, and **Run**.
- After it finishes, a chart of one metric (kinetic energy) over time with **two lines**: the original and the changed version.
- Results are saved with the universe and shown again when it is reopened.

How it works:
- An experiment starts from the universe's saved state, applies the change to a copy, runs both for N ticks, and records the metric every few ticks.
- Stored as `experiments/<id>/experiment.json` (what changed, ticks, seed) and `results.json` (the series), plus a small **run record**: engine version, seed, backend, time taken. This is what makes a result reproducible later.

What already exists: `experiment.branch`, `experiment.run`, metrics and snapshots in `simtara-api`. What is new: saving experiments and results to disk and drawing the chart in the Studio.

Done when: run "gravity 2 vs 4", see two curves that differ, close and reopen, and the chart is still there. Running the same experiment again gives the same numbers on CPU.

## Out of scope for 0.3.0

The template gallery and other kinds of universe, the project layer above universes, docking panels, parameter sweeps, sharing `.simtara` files, hosted compute, accounts and permissions. All are in the vision file and come later, one at a time.

## Suggested order of work

1. `universe.json` + folder layout + save/load functions in a small new library crate (no UI).
2. Studio: Save button, My universes list.
3. Experiment storage in the same crate, using the API that exists.
4. Studio: Experiment panel and two-line chart.
5. Update docs and the learning log; cut v0.3.0.

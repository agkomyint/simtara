# SimTara docs

Start here. These docs are written so we can learn the project together as it grows.

| Read this | When |
|---|---|
| [concepts.md](concepts.md) | You want plain-English meanings: world, tick, module, system, snapshot, metric, backend |
| [architecture.md](architecture.md) | You want to know which crate/file does what, and how a request flows through |
| [learning-log.md](learning-log.md) | You want to remember why we decided something, or add a question to study |
| [business.md](business.md) | What we could sell: app, hosted compute, packages, marketplace |
| [roadmap/v0.3.0.md](roadmap/v0.3.0.md) | What we are building next (small) |
| [roadmap/vision.md](roadmap/vision.md) | Where it could go long term (big, not scheduled) |

## How we keep these docs useful

- When we add or change something, update the matching page in the same commit.
- When we make a decision, add a dated entry to the learning log: what, why, what we rejected.
- When something confuses you, put it under "Open questions" in the learning log. We answer it there and move the answer into `concepts.md`.
- Keep it short. A page nobody reads is worse than no page.
